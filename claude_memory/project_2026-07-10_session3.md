## Riccardo's clarification on Task 4.5 categories (CH/P/NH/O/E/A) — major reframe, not a tiebreaker

Sent an email answering the CH/P question raised earlier this session. **The categories classify the ontological TYPE of the comparison's TARGET (comparé), not the semantic domain of the trait/quality being illustrated.** His own example: id 153, "Je bats lâchement en retraite... comme un rat" — the target of the comparison is "il" (a person), so **CH**, regardless of the fact that the illustrated trait (lâcheté/cowardice) is a personality trait. Contrast cases he gave: "Mes émotions se cachaient comme des rats" → target = "mes émotions" (psychological entity) → **P**. "L'île ressemblait à un rat" → target = "l'île" (natural/geographic entity) → **E**. Same vehicle (rat), same rough action, different category purely based on what kind of thing the target is.

**This means the CH/P "Piège fréquent" fix applied earlier in the day (2026-07-10, telling the model "personality traits → P, not CH") was built on the wrong theory of the category and was pushing the model in exactly the wrong direction** — see [[feedback_ecopoetique_experiments]] and the 68.3% regression noted in [[project-2026-07-10-session]]. It also means the earlier "12+ gold rows mislabeled CH for personality traits" finding from this session's audit of `resultats_task45_compare_category.csv` was **not a gold error at all** — gold was right, our reading of the category was wrong. Do not re-litigate those rows as mislabels.

**Not yet done**: `comparison/run_task45_compare_category.py`'s prompt needs a full rewrite around "identify the target's ontological entity type" (human/psychological-state/animal-plant-bio-process/natural-element/artificial-object/abstract-concept) rather than "identify the semantic domain of the illustrated trait." This is a bigger change than the two prior CH/P patches — those were incremental tweaks to a wrong model, this needs the underlying instruction restructured. Should be done and small-batch tested (same 20-row targeted-batch protocol used for Task 2's v6 fix) before running the full 104-row gold set again.

Other Task 4.5 issues found earlier this session, independent of the CH/P reframe, still stand:
- Zero NH (non-human living-thing target) examples anywhere in the 200-row gold set — structural gap, needs new gold rows, not a model fix. Flag explicitly when building the new gold set (task #1 below) — ask Riccardo to ensure NH coverage this time.
- CH vs A confusion on voice/song/artistic-expression metaphors (small, 2 rows) — likely same root mechanism as the old CH/P over-triggering, revisit after the entity-type rewrite.
- Individual mislabel candidates flagged earlier ("ver luisant"/mamelon should arguably be CH not E; "myrtilles"/béton-stain arguably O not E) — these are about physical-object-vs-natural-element boundary, not affected by the CH/P reframe, still worth Riccardo's eyes but lower priority than the entity-type rewrite.

## Task 2 — v6 prompt fix (4 changes), tested small-batch then full gold set: 66.7% → 69.3%, confirmed real

Applied 4 changes to `run_task2_subcategories.py`'s decision-tree prompt, targeting the diagnosis from earlier this session (25/38 errors were 3 catch-all categories — META_ATTR, DE_PARANGON, LOC_IDIOM — swallowing more-specific categories checked later in the tree):
1. LOC_IDIOM (question 1): added an explicit mandatory self-check ("mentally remove 'comme'+token — does a concrete literal event remain? If yes, not LOC_IDIOM") rather than just listing more example phrases, since the prior fix (2026-07-10 earlier, v5) had literally listed "tomber comme des mouches" as an excluded example and the model still got that exact phrase wrong — a general procedural check was tried instead of more examples.
2. MOD_ANALOG (question 8): broadened trigger phrases to include self-perception constructions ("se voir", "se sentir devenir", "s'imaginer en") alongside the existing "sembler/on dirait/avoir l'air de".
3. DE_PARANGON (question 11): added an exclusion redirecting to META_ATTR (question 12) when the "N de N2" phrase is actually the predicate of an identity copula ("il est LE cerf de ma vie" — a real identity assertion, not a standalone qualité-illustrée-par phrase).
4. META_ATTR (question 12) / META_VERB (question 13): added an exclusion for hypothetical/conditional copulas ("si X était Y" → COMME_SI or META_FILEE, not META_ATTR) plus explicit contrastive examples distinguishing the two ("le mot-clé EST l'identité affirmée" → META_ATTR vs. "le mot-clé est sujet d'un VERBE D'ACTION incompatible" → META_VERB).

**Validation protocol used** (worth reusing as the standard going forward, matches [[feedback_ecopoetique_experiments]]'s "validate small batches first"): built `test_task2_smallbatch_v6.py`, a 20-row targeted batch (15 previously-wrong rows concentrated in the fixed categories + 5 previously-correct rows as a regression check), before touching the full 114-row set. Result: 11/20 (55%, not directly comparable to overall accuracy since the sample is deliberately skewed toward hard rows), but the real signal was **6/15 targeted errors fixed, 0/5 regressions** — a clean win, no backfire pattern (unlike the earlier v5 LOC_IDIOM fix and the Task 4.5 CH/P fix, both of which barely moved the needle or regressed). This was the explicit green-light signal to scale to the full set.

**Full 114-row result** (after correctly archiving the stale v5 output file first — the validation script `validate_task2_gold.py` silently *resumes* from any existing output file rather than starting fresh, which would have kept old v5 predictions for the 76 already-done rows and invalidated the comparison; caught and fixed before it wrote anything): **79/114 = 69.3%**, up from v5's 66.7% (76/114). A real, if modest, improvement — +3 correct rows net. Saved to `métaphore/resultats_task2_gold_validation.csv` (old v5 archived as `resultats_task2_gold_validation_v5_ARCHIVE_20260710_133254.csv`). Still well below the 80% bar needed to scale to the full corpus. **Not yet re-diagnosed** — should re-run the confusion-matrix pass on this new set of wrong rows before the next fix attempt, same as was done for v5.

**Lesson reinforced**: this is the second time this pattern has appeared this session (Task 2 catch-all fix = real win; Task 4.5 CH/P fix = real regression) — the small-batch-first protocol correctly predicted both outcomes in advance (6/15 fixed 0 regressions → real full-set win; would likely have shown regressions on Task 4.5's second fix if it had been used there too, but that fix went straight to the full 104-row set without a small-batch check first). **Always use the small-batch-with-regression-check protocol before any full gold-set re-run going forward**, not just when convenient.
